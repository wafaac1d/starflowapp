# Рабочий цикл StarFlow

Каждый из девяти срезов ниже выполняется одним и тем же циклом. Тексты девяти отдельных промптов в запросе на документы не приложены. Границы срезов выведены из `idea.md`, чтобы следующий промпт попадал в один срез и не переписывал соседние.

Новая развилка внутри среза записывается в `docs/DECISIONS.md` до того, как код начнёт на неё опираться. Ход и фактические команды записываются в `docs/PROGRESS.md`.

## Цикл

1. Контекст. Прочитать `idea.md`, `conventions.md`, `rules.md`, `workflow.md`, `docs/DECISIONS.md` и `docs/PROGRESS.md`. Для правки интерфейса дополнительно прочитать `docs/DESIGN.md`. Отметить, какой срез уже закрыт и какие ограничения окружения живы.
2. План. Коротко перечислить файлы, сценарии, миграции и проверки этого среза. Явно назвать соседние срезы, которые сейчас не делаются.
3. Код. Реализовать только план. Рабочий код сразу связывает кнопку, API, сценарий и базу, если этот путь входит в срез.
4. Тесты. Покрыть доменные границы, хранение и отказные ветки среза. Платёж, подпись Telegram и календарные границы проверять боевым алгоритмом на тестовых входных данных.
5. Lint, типы и сборка. Запустить проверки, которые относятся к затронутому коду:
   - backend: `uv run ruff check`, `uv run ruff format --check`, `uv run mypy`, `uv run pytest`;
   - frontend: `pnpm exec tsc --noEmit`, `pnpm exec vitest run`, `pnpm exec vite build`;
   - сквозной путь, если срез меняет экран: Playwright.
6. Документация. Обновить `docs/DECISIONS.md`, если появилась развилка. Обновить `docs/PROGRESS.md` командами, кодами выхода и тем, что запустить не удалось.
7. Отчёт. Написать, что сделано, какие проверки зелёные, какие ограничения остались. Не называть шрифт, логотип, лицензию эфемерид или WCAG выполненными, если соответствующий пункт `docs/PROGRESS.md` этого не подтверждает.

Срез, в котором проверка упала, не закрывается точечным подавлением ошибки.

## Срезы

### 1. Каркас

Собрать uv-проект, пакет `src/starflow`, pnpm-проект frontend, Dockerfile и compose из `app` и `postgres`. ASGI отдаёт `/api/v1/health` и статику Vite. В процессе стартуют пустой состав bootstrap, structlog и Alembic с первой миграцией метаданных. Дизайн-токены, базовые UI-компоненты, ресурс `ru.ts` и слот логотипа появляются здесь. OFL-файлы `Google Sans` подключаются, если лежат в согласованном каталоге; при их отсутствии остаётся fallback и открытый пункт в прогрессе.

В срез не входят профиль, расчёты, оплата и экраны гороскопа.

Готовность: compose поднимает оба сервиса, health отвечает, frontend открывается с того же origin, ruff, mypy, pytest, tsc, Vitest и Vite build выполнены.

### 2. Сессия и профиль

Проверять `initData`, создавать пользователя и сохранять профиль: имя, дата, необязательное время, место, координаты, пояс. Поиск места — отдельное действие с кэшем и лимитом. Удаление данных полностью убирает персональные строки и оставляет обезличенную строку платежа, когда она уже есть.

В срез не входят тексты прогнозов и Stars.

Готовность: неверная подпись отклоняется, неизвестное время сохраняется как неизвестное, повторный геокодерный запрос читает кэш, удаление проверено тестом на PostgreSQL.

### 3. Эфемериды

Подключить порт расчёта и реализацию `pyswisseph`. Посчитать положения, знак Луны, дома и асцендент для известного времени. Для неизвестного времени дома и асцендент отсутствуют. Зафиксировать в прогрессе, что выбор лицензии Swiss Ephemeris ещё впереди, если он не сделан.

В срез не входят пользовательские тексты и paywall.

Готовность: контрольные положения проходят с допуском, неизвестное время не создаёт асцендент, публичный запуск по-прежнему отмечен как закрытый до лицензии.

### 4. Бесплатный контур

Сделать день, неделю, совет и Луну, одну совместимость на местную календарную неделю и одно уведомление-дайджест. Тексты лежат в ресурсах. Планировщик отправляет включённый дайджест и не шлёт его повторно в те же местные сутки.

В срез не входят premium-разборы и оплата.

Готовность: вторая совместимость в ту же неделю возвращает прежний результат, граница понедельника покрыта `time-machine`, выключенное уведомление не уходит.

### 5. Подписка и подарки

Прочитать тарифы из YAML. Mini App просит invoice link у API и открывает его через `WebApp.openInvoice`. Доступ даёт только проверенный `successful_payment`. Повтор charge id идемпотентен. Подарок — разовый счёт без `subscription_period`, код и одно погашение. Себе подарок не активируется.

В срез не входят тексты карт и помощник. Кнопки оплаты вызывают реальный invoice flow. Автоматические тесты подменяют Telegram. Живой платёж без реального списания не считается проверенным.

Готовность: период появляется только после подтверждённого update, двойная доставка не удваивает срок, YAML остаётся единственным источником цены.

### 6. Premium-контент

На активном периоде открыть персональные день и неделю, темы, натальную карту, астрокалендарь и синастрию. Без периода API возвращает `premium_required`, а экран показывает paywall из ресурса.

В срез не входят квота помощника и админка.

Готовность: каждый premium-маршрут отказан без периода и выполнен с периодом. Копирайтинг не обещает точное событие.

### 7. Помощник и ретро

Хранить промпты в ресурсах. Считать 20 вопросов на период в базе. Двадцать первый запрос возвращает `assistant_quota_exhausted`. Ретро строится по тому же профилю и периоду. Ответ модели проверяется на emoji. Регистр ответа сохраняется.

В срез не входят рефералы и админ.

Готовность: квота переживает перезапуск, граница периода покрыта `time-machine`, дисклеймер виден до отправки.

### 8. Удержание

Сделать избранное, близких, реферальный код, оценки, streak и share. Награда реферала начисляется один раз после первого подтверждённого платежа приглашённого. Share не содержит данных рождения. Streak растёт один раз за местные сутки и сбрасывается после пропуска.

В срез не входит админ-панель.

Готовность: лимиты YAML соблюдены, самореферал отклонён, пропуск суток покрыт тестом.

### 9. Админ и приёмка

Собрать админ-раздел для `STARFLOW_ADMIN_IDS` с журналом ручной выдачи периода. Пройти Playwright по профилю, бесплатному дню, paywall, отказу квоты и удалению данных. Сверить образ: один worker, сервисы compose, логотип, шрифт и лицензия шрифта. Обновить критерии готовности из `idea.md` фактическими результатами.

Готовность: список критериев в `docs/PROGRESS.md` либо закрыт командой и результатом, либо явно оставлен открытым с причиной.

## Форма отчёта

Отчёт среза короткий:

- какой срез закрыт;
- какие сценарии теперь работают;
- команды и коды выхода;
- что не запускалось и почему;
- какие пункты готовности остаются открытыми: логотип, шрифт, лицензия эфемерид, WCAG, токен бота, ключ DeepSeek.
