# Решения StarFlow

Дата решений: 2026-10-21. Статус всех записей ниже — принято, пока отдельная запись его не сменит.

## D-001. Один процесс на API, бота и планировщик

Контекст. Mini App, webhook и расписание должны жить рядом с PostgreSQL. Отдельные frontend, Redis и брокер увеличивают состав рантайма.

Решение. `docker-compose.yml` содержит только `app` и `postgres`. Образ `app` собирает frontend и отдаёт его тем же ASGI, который принимает API и webhook. `AsyncIOScheduler` работает в том же процессе. Production запускает один ASGI worker и одну реплику.

Причины. Polling и планировщик при двух процессах выполняют одну и ту же работу дважды. Один origin упрощает сессию Mini App и убирает отдельный CORS-контур.

Альтернативы. Отдельный контейнер Vite и Redis для очереди уведомлений. Несколько worker за Gunicorn.

Последствия. Горизонтальное масштабирование `app` запрещено, пока новое решение не опишет выбор лидера. На старте процесс берёт advisory lock `starflow_singleton` и завершается, если lock уже занят. Это предохранитель, а не схема масштабирования.

## D-002. Ручная композиция и протоколы репозиториев

Контекст. Нужны тестируемые границы без скрытого контейнера зависимостей.

Решение. `bootstrap` собирает объект зависимостей вручную. Репозитории и внешние порты описаны как `Protocol`. Unit of work владеет `AsyncSession` и единственный вызывает `commit`.

Причины. Состав зависимостей виден в одном модуле. Тест подменяет порт без фреймворка внедрения.

Альтернативы. `dependency-injector`. Сессия, открытая в роутере. Коммит внутри репозитория.

Последствия. Новый сервис регистрируется в `bootstrap`. Роутер, хендлер бота и задание планировщика остаются транспортными.

## D-003. Контракт JSON и клиент из OpenAPI

Контекст. Frontend и backend меняются одним репозиторием, но типы легко разъехать.

Решение. Pydantic-схемы — источник OpenAPI. Поля JSON — `snake_case`. TypeScript-типы генерируются `openapi-typescript`. Сессия передаётся заголовком `Authorization: TMA <initData>`.

Причины. Одна схема обслуживает проверку входа и клиент. `snake_case` совпадает с Python и колонками.

Альтернативы. Ручные TypeScript-интерфейсы. `camelCase` в JSON с промежуточным преобразованием.

Последствия. Изменение ответа начинается со схемы и генерации клиента. Сообщение ошибки пользователю берётся из ресурса, код ошибки стабилен.

## D-004. Telegram Stars как единственные деньги

Контекст. Premium и подарки требуют оплаты. Фиктивный успех оплаты ломает доверие к квотам.

Решение. Счёт выставляется через Telegram Bot Payments в валюте Stars. Период создаёт обработчик `successful_payment` после проверки payload. Идемпотентность обеспечивает уникальный `telegram_payment_charge_id`. Админская выдача периода пишется в журнал отдельно и не маскируется под платёж.

Причины. У Mini App уже есть платёжный контур Telegram. Второго эквайера в составе сервисов нет.

Альтернативы. Внешняя касса отдельным сервисом. Клиентская кнопка, которая сама включает premium.

Последствия. Локальный тест передаёт в обработчик структуру update и не включает premium мимо этого обработчика. Без токена бота живой invoice в отчёте не считается проверенным.

## D-005. pnpm и uv

Контекст. Нужны воспроизводимые установки backend и frontend.

Решение. Python-зависимости ведёт `uv`, lockfile — `uv.lock`. Frontend ведёт pnpm, точная версия — в поле `packageManager`, lockfile — `frontend/pnpm-lock.yaml`. CI и Docker ставят frontend с `--frozen-lockfile`, backend — с `uv sync --frozen`.

Причины. Оба менеджера фиксируют дерево зависимостей. pnpm не поднимает неявные пакеты из чужих зависимостей, что совпадает со strict TypeScript.

Альтернативы. pip и requirements.txt. npm и `package-lock.json`. Bun.

Последствия. В образе нужен Corepack или явный pnpm объявленной версии. Второй lockfile frontend не добавляется.

## D-006. Google Sans как самохостинг OFL

Контекст. Интерфейс требует семейство `Google Sans` и запрещает тихую подмену на `Google Sans Text`, `Product Sans` и другие семьи. Нужно было проверить право на подключение и распространение.

Проверка 2026-10-21.

- [Google Fonts FAQ](https://developers.google.com/fonts/faq) отвечает, что с ноября 2025 `Google Sans` и `Google Sans Flex` доступны по SIL Open Font License. `Product Sans` по-прежнему только для продуктов Google.
- В [google/fonts `ofl/googlesans`](https://github.com/google/fonts/tree/main/ofl/googlesans) лежат `GoogleSans[GRAD,opsz,wght].ttf`, `GoogleSans-Italic[GRAD,opsz,wght].ttf`, `OFL.txt` и `TRADEMARKS.md`.
- Прочитанный `OFL.txt` — SIL OFL 1.1, copyright 2025 The Google Sans Project Authors, reserved font name в заявлении copyright не указан. Лицензия разрешает встраивать и распространять шрифт вместе с ПО, если рядом есть текст лицензии, и запрещает продавать шрифт отдельно.
- `METADATA.pb` называет семейство `Google Sans`, лицензию `OFL`, ось веса 400–700 и оптический размер 17–18. В подмножествах есть кириллица.
- `TRADEMARKS.md` называет «Google» и «Google Sans» товарными знаками. Использование шрифта не даёт права создавать впечатление связи с Google или включать эти знаки в имя продукта.
- Страница атрибуции Google Fonts в прочитанном снимке всё ещё пишет для файлов строку `Copyright 2017 Google, Inc. All Rights Reserved`. Это расходится с `OFL.txt` той же директории. Двоичные таблицы имён в этой сессии не снимались: файлы шрифта в репозиторий не скачивались.

Решение. В продукт войдёт только семейство с именем `Google Sans` из `ofl/googlesans`, оба файла variable/italic, плюс `OFL.txt` и `TRADEMARKS.md` в образе по читаемому пути. CSS-имя — `"Google Sans"`. `font-display: block`. Веса интерфейса — 400, 500, 600, 700. Загрузка с `fonts.googleapis.com` не используется: запрос шрифта не должен уносить IP пользователя Mini App на сервер Google, а образ должен содержать файлы сам.

`Google Sans Flex`, `Google Sans Code`, `Google Sans Text` и `Product Sans` не подключаются.

Причины. Официальный каталог и лицензия рядом с файлами разрешают распространение оригинальной версии. Узкая ось веса — свойство именно этой семьи, а не повод сменить её на Flex.

Альтернативы. CSS API Google Fonts. Подмена на Flex ради более широких осей. Ожидание, что шрифт установлен в операционной системе пользователя.

Последствия. Требование к шрифту выполнено только после того, как эти файлы попадут в сборку и в отчёте будет сверка лицензии скачанной ревизии. До этого fallback — общий `sans-serif`, и он требованием не является. При вендоринге нужно сверить copyright внутри бинарника с сопровождающим `OFL.txt`. Если у скачанной ревизии нет OFL, подключение останавливается. В интерфейсе и названии продукта товарный знак Google не используется.

## D-007. Логотип только из `static/logo.png`

Контекст. Знак продукта пользователь кладёт сам в `static/logo.png`.

Решение. Сборка копирует этот файл в выдачу frontend как `/logo.png`. Компонент `LogoSlot` показывает его без перерисовки. Если файла нет, слот остаётся пустой поверхностью и не создаёт `<img>` с отсутствующим адресом. Production-сборка образа падает, если файла нет. Локальная разработка каркаса может идти с пустым слотом, и это видно в прогрессе.

Причины. Замена или сгенерированный знак подменят бренд. Сломанная иконка выглядит как ошибка продукта.

Альтернативы. Временный SVG. Отсутствие слота до появления файла.

Последствия. На 2026-10-21 файла в репозитории нет. Критерий логотипа открыт.

## D-008. Контраст вторичного цвета

Контекст. Палитра задана: текст `#9b2d30`, вторичный текст `#b8b8b8`, фон `#f5f0f0`. Её нельзя тихо менять. Соответствие WCAG нельзя заявлять при недостаточном контрасте.

Проверка по формуле относительной яркости WCAG 2.x, посчитана локально 2026-10-21:

| Пара | Отношение | AA для обычного текста 4.5:1 | AA для крупного текста 3:1 |
| --- | --- | --- | --- |
| `#b8b8b8` на `#f5f0f0` | 1.757:1 | нет | нет |
| `#9b2d30` на `#f5f0f0` | 6.617:1 | да | да |
| `#f5f0f0` на `#9b2d30` | 6.617:1 | да | да |
| `#ffffff` на `#9b2d30` | 7.469:1 | да | да |

Решение. Палитра остаётся. Вторичный цвет используется для повторяющейся подписи, которая не несёт единственную копию цены, ошибки, лимита, предупреждения, даты рождения или условия подписки. Такие сведения набираются `#9b2d30`. Подпись кнопки на заливке `#9b2d30` — `#f5f0f0`. Карточка может быть белой поверх фона; белый не становится цветом смыслового текста. Соответствие WCAG не заявляется: вторичный цвет не проходит даже порог крупного текста, основной на фоне проходит порог обычного текста AA и не проходит порог AAA 7:1.

Причины. Требование сохранить палитру сильнее желания подогнать вторичный цвет под калькулятор контраста. Критичный смысл при этом остаётся на цвете, который на фоне читается.

Альтернативы. Затемнить `#b8b8b8`. Отказаться от вторичного цвета. Заявить соответствие WCAG только для основного цвета.

Последствия. Дизайн остаётся тихим, а часть мета-подписей слабее основного текста. Это зафиксированный конфликт требований, а не недосмотр реализации.

## D-009. Строчные авторские тексты без глобального регистра

Отменено решением D-051. Ниже — прежняя запись, она больше не задаёт регистр.

Контекст. Все авторские тексты интерфейса, включая помощника, должны быть строчными. Имена и идентификаторы — в исходном регистре.

Решение. Строки хранятся строчными в ресурсах. CSS не понижает регистр документа. Помощник получает запрет прописных и emoji в промпте. Ответ с emoji или с прописной вне переданных имён отвергается и один раз запрашивается снова. `lower()` ко всему ответу не применяется.

Причины. Глобальный `text-transform` испортил бы имена, коды и URL. Постфактум `lower()` сделал бы то же внутри фразы модели.

Альтернативы. Понижать регистр всей страницы стилем. Принимать любой регистр модели.

Последствия. Ресурсный тест следит за прописными в авторских строках. Имена вставляются отдельными значениями.

## D-010. Эфемериды через pyswisseph и лицензионный шлюз

Контекст. Расчёт можно было строить на `pyswisseph` или на `kerykeion`. Swiss Ephemeris распространяется по двойной лицензии: AGPL-3.0 или профессиональная лицензия Astrodienst. Выбор нужен до распространения и до включения публичного сервиса. `kerykeion` сам под AGPL-3.0; его backend по умолчанию — `libephemeris`, тоже AGPL-3.0, а Swiss Ephemeris там необязательный backend.

Решение. Порт `Ephemeris` реализуется на `pyswisseph`. `kerykeion` не подключается. Публичный сервис не считается готовым, пока владелец продукта отдельной записью не выберет одно из двух: весь сервис под AGPL-3.0 с исполнением её условий, либо купленная профессиональная лицензия Swiss Ephemeris и работа без других AGPL-библиотек расчёта.

Причины. Прямой порт не добавляет вторую AGPL-обвязку, у которой в прочитанных материалах не виден коммерческий обход. Профессиональная лицензия имеет смысл только если сам расчётный код не тянет ещё одну AGPL-библиотеку.

Альтернативы. `kerykeion` с `libephemeris`. Сразу принять AGPL на весь репозиторий. Отложить расчёты до покупки лицензии и не писать адаптер.

Последствия. Локальная разработка и тесты контрольных положений допустимы. Критерий публичной готовности остаётся открытым. Имена Astrodienst не используются в рекламе продукта.

## D-011. Геокодер Nominatim с кэшем и локальным поясом

Контекст. Место рождения нужно превратить в координаты, затем в пояс IANA. Публичный Nominatim ограничен [политикой использования OSMF](https://operations.osmfoundation.org/policies/nominatim/): не больше одного запроса в секунду на всё приложение, свой User-Agent или Referer, атрибуция, кэш, запрет подсказок на каждый символ. Приложение должно уметь сменить адрес сервиса без обновления клиента.

Решение. Поиск места — явное действие пользователя и серверный запрос. Результаты кэшируются в PostgreSQL. Общий лимитер процесса — один запрос в секунду. User-Agent задаётся настройкой. На экране места видна атрибуция «© OpenStreetMap contributors». Базовый URL настраивается. Пояс считается офлайн библиотекой `timezonefinder`.

Причины. Профиль запрашивает место редко, если ответы кэшируются. Пояс по координатам не требует ещё одной сети. Смена URL выполняет требование политики о возможности переключить сервис.

Альтернативы. Подсказки на каждую букву. Отдельный коммерческий геокодер сразу. Хранение только строки места без координат.

Последствия. При росте аудитории публичный экземпляр перестанет подходить, и URL сменится на свой Nominatim или другого провайдера с тем же портом. Пока используется публичный экземпляр, массовое заполнение профилей скриптом запрещено.

## D-012. Календарь пользователя и неизвестное время

Контекст. Бесплатная совместимость, streak и дайджест зависят от «сегодня». Время рождения может быть неизвестно.

Решение. Границы суток и недели считаются в часовом поясе профиля. Неделя начинается в понедельник в 00:00. Streak растёт один раз за местные сутки, когда открыт дневной текст. Если время рождения неизвестно, оно хранится пустым, планеты считаются на местный полдень, дома и асцендент не создаются, Луна у границы знака помечается как менее определённая.

Причины. Общие сутки UTC расходятся с вечером пользователя. Вымышленное время рождения создало бы ложные углы карты.

Альтернативы. Скользящие 7 дней с момента первого расчёта. Солнечные дома при неизвестном времени. Отказ считать планеты без времени.

Последствия. Тесты границ идут через `time-machine` и зону профиля. Текст карты прямо говорит, каких элементов нет.

## D-013. Квоты и тексты помощника

Контекст. На период подписки дано 20 вопросов. Ответ модели — пользовательский текст со своими ограничениями регистра и emoji. Запрос уходит во внешний DeepSeek.

Решение. Квота хранится в PostgreSQL и уменьшается в той же транзакции, что и сохранённый вопрос. Промпты лежат в файлах ресурсов. До отправки экран сообщает, что текст уходит внешнему сервису и что материал развлекательный. Модель вызывается официальным SDK `openai` с базовым URL из настроек.

Причины. Квота в памяти процесса обнулилась бы при рестарте. SDK OpenAI совпадает с совместимым API DeepSeek и не требует отдельного клиента.

Альтернативы. Свой HTTP-клиент к DeepSeek. Перенос неиспользованных вопросов на следующий период.

Последствия. Нет ключа — сценарий помощника в отчёте не считается проверенным на живом API. Контрактный тест с подменённым портом проверяет квоту и фильтр ответа.

## D-014. Что остаётся после удаления данных

Контекст. Пользователь может удалить данные. Платёж Telegram при этом может понадобиться для сверки.

Решение. Удаляются профиль, расчёты, тексты, избранное, близкие, диалог, оценки, streak и реферальные связи. Остаётся строка с идентификатором платежа, суммой, валютой и периодом, без имени, даты рождения, места и содержания переписки.

Причины. Повторная доставка того же charge id не должна снова открыть удалённый период и не должна потерять след уже принятых денег.

Альтернативы. Удалять и строки платежей. Хранить полный профиль в архиве.

Последствия. Экран удаления говорит, что след платежа без данных рождения сохраняется. Отдельного скрытого архива гороскопов нет.

## D-015. Визуальный язык собственных компонентов

Контекст. Нужен спокойный premium-интерфейс без чужой библиотеки компонентов и без визуального шума.

Решение. Компоненты свои. Кнопки — радиус `999px`, касание от 44px, общая шкала состояний. Поверхности белые на `#f5f0f0`, граница и тень смешаны из `#9b2d30` с малой долей. Градиентов нет. Иконки — SVG со штрихом 1.5. Палитра StarFlow сохраняется поверх цветов темы Telegram. Навигация собирается собственными кнопками внутри WebView. Emoji в анимациях не используются: разрешение на них необязательное, а набор иконок уже задан SVG.

Причины. Чужая система компонентов принесёт свои радиусы, цвета и плотность. `MainButton` Telegram не держит заданную типографику. Опциональные emoji в анимации размоют запрет emoji в интерфейсе.

Альтернативы. Готовая библиотека с переопределённой темой. Системная кнопка Telegram. Редкие emoji в загрузочной анимации.

Последствия. Каждый новый контрол проходит через `components/ui` и токены. Safe area, фокус, клавиатура и `prefers-reduced-motion` входят в базовые компоненты, а не в отдельный проход «потом».

## D-016. Каталоги каркаса и имена окружения

Контекст. Срез каркаса задал дерево `src/starflow/{domain,astro,ai,services,cache,repositories,db,api,bot,scheduler,i18n}`, тексты в `resources/`, миграции в `migrations/` и конкретные имена переменных без префикса `STARFLOW_`.

Решение. Код следует этому дереву. Сценарии лежат в `services`. Тарифы — в `resources/plans.yaml`. Схемы — в `migrations`. Переменные называются как в `.env.example`.

Причины. Имена уже заданы для запуска и CI. Второй префикс рядом с ними разведёт конфигурацию.

Альтернативы. Оставить ранний набросок с `application/`, `infrastructure/` и префиксом `STARFLOW_`.

Последствия. Ранние пункты conventions про каталоги и префикс заменены этим решением. Секреты по-прежнему не попадают в репозиторий и в `VITE_*`.

## D-017. Polling по умолчанию, webhook по паре настроек

Контекст. Ранний текст conventions считал webhook режимом production. Срез каркаса требует обратное: polling по умолчанию, webhook опционально, с секретом и без одновременной работы обоих режимов.

Решение. Пустой `WEBHOOK_URL` означает polling. Непустой URL означает webhook и требует `WEBHOOK_SECRET` и путь в URL. Процесс регистрирует один `Bot` и один `Dispatcher`. В режиме polling `POST` на путь webhook отвечает 404 и не кормит dispatcher. В режиме webhook запрос без верного заголовка `X-Telegram-Bot-Api-Secret-Token` отвечает 401.

Причины. Локальный и первый production-контур могут работать без публичного HTTPS. Секрет отличает webhook Telegram от чужого POST.

Альтернативы. Отдельная переменная `BOT_MODE`. Всегда включённый webhook.

Последствия. Обрыв Telegram не валит `/health`: супервизор бота повторяет попытку и не участвует в проверке живости. Проверка живости смотрит только процесс и, для `/health` и `/readiness`, `SELECT 1` к PostgreSQL.

Если страница цен и новость о маршрутизации Pro разойдутся с фактическим ответом API, меняется конфигурация, а не вызовы по коду. ## D-020. Долговечность рассылки в outbox, задание планировщика в коде

Контекст. Отдельного брокера нет. Повторяемое задание одно: забрать готовую рассылку.

Решение. `AsyncIOScheduler` держит интервальное задание в памяти процесса и регистрирует его при старте. Строки рассылки лежат в `notification_outbox`. Захват строк идёт `FOR UPDATE SKIP LOCKED`, отправка выполняется после коммита захвата, повторный `local_date` для той же пары пользователя и вида запрещён уникальным ключом. Зависший статус `sending` возвращается в работу.

Причины. Определение задания и так находится в коде, переживать рестарт ему не нужно. Переживать рестарт должны сами уведомления. SQLAlchemy job store добавил бы вторую схему ради одного интервала.

Альтернативы. Job store APScheduler в PostgreSQL. Redis.

Последствия. Несколько реплик по-прежнему запрещены. Уникальный ключ и блокировка строк остаются защитой от двойной отправки внутри одного процесса и от повторной вставки. Ошибка чтения outbox не печатает SQL и параметры: задание логирует только имя исключения.

## D-021. Проверка живости не смотрит наружу

Контекст. Healthcheck контейнера `app` не должен зависеть от DeepSeek и Telegram.

Решение. `/liveness` проверяет только процесс. `/health` и `/readiness` выполняют `SELECT 1` к PostgreSQL и больше ничего. Docker healthcheck вызывает `/health`. Недоступность базы после старта делает проверку неуспешной, недоступность Telegram или DeepSeek — нет.

Причины. База — локальная зависимость compose, без неё API не готов. Внешние API не должны перезапускать процесс.

Альтернативы. Одна проверка на все внешние сервисы. Healthcheck только по `/liveness`, без базы.

Последствия. Сбой бота логируется супервизором и не меняет код healthcheck. Ключ DeepSeek на старте проверяется как непустая строка, сетевой вызов к API не делается.

## D-022. Сигнатуры aiogram оставляют Any

Контекст. `BaseSession` и `BaseMiddleware` в aiogram 3 объявлены через `Any`. Переопределение с более узким словарём не совпадает с базовым методом.

Решение. Переопределения в `bot/session.py` и `bot/handlers.py` повторяют библиотечные сигнатуры с `Any`. В остальном коде `Any` не используется.

Причины. Это контракт библиотеки, а не собственный тип StarFlow.

Альтернативы. Игнорировать несовпадение типов. Не наследовать middleware и собирать цепочку вручную.

Последствия. Два файла содержат `Any` только в этих сигнатурах. Удалять его можно вместе со сменой версии aiogram, если библиотека сузит типы.

## D-023. HTTP-клиент официального SDK

Контекст. DeepSeek вызывается через официальный OpenAI SDK. На 2026-10-21 `uv.lock` разрешил `openai` 3.35.1. Конструктор `AsyncOpenAI` в этой версии типизирует `http_client` как `httpx2.AsyncClient`. Пакет `httpx2` 2.16.0 — отдельный дистрибутив от `httpx` 0.28, которым ASGI-тесты ходят в приложение.

Решение. `DeepSeekClient` создаёт и закрывает клиент `httpx2`. Зависимость объявлена прямо. Тест клиента подставляет `httpx2.MockTransport` и проверяет имя модели и `response_format`. `httpx` остаётся транспортом ASGI-тестов. `complete` не вызывается из `/health`, `/liveness` и `/readiness`.

Причины. Клиент `httpx.AsyncClient` не совпадает с типом SDK 3.35.1 и не является тем транспортом, которым этот SDK отправляет запрос.

Альтернативы. Не передавать HTTP-клиент и подменять метод SDK. Зафиксировать SDK первой линии, если он принимает обычный `httpx`. Откат не делался: lock уже выбрал 3.35.1 при нижней границе `>=1.55`; верхняя граница теперь `<4`.

Последствия. Живой вызов DeepSeek этим решением не подтверждается. Имя модели по-прежнему берётся только из настроек.

## D-024. Дыры типов APScheduler и конструктор настроек

Контекст. `mypy --strict` останавливается на двух библиотечных местах. У `apscheduler` 3.11.3 нет `py.typed` и stubs. `pydantic-settings` читает обязательные поля из окружения, а обычный mypy требует их как аргументы `Settings()`.

Решение. Для модуля `apscheduler.*` в mypy включено `ignore_missing_imports`. Подключён плагин `pydantic.mypy`, чтобы конструктор настроек не требовал полей, которые приходят из окружения. Планировщик по-прежнему создаёт `AsyncIOScheduler` явно.

Причины. Точечное исключение одной библиотеки без типов уже, чем ослаблять strict на всём пакете. Плагин описывает реальное поведение `BaseSettings`, а не прячет ошибку в коде.

Альтернативы. Писать собственные stubs APScheduler. Вызывать `Settings` с `# type: ignore`.

Последствия. Ошибки внутри APScheduler mypy не видит. Override можно снять, когда у библиотеки появятся типы.

## D-025. Mini App по документации Telegram на 2026-10-21

Контекст. Перед сессией и онбордингом прочитана страница [Telegram Mini Apps](https://core.telegram.org/bots/webapps).

Проверено на этой странице:

- Запуск возможен с кнопки профиля, клавиатуры, inline-кнопки, menu button, inline mode, прямой ссылки и меню вложений. Menu button задаётся в BotFather или методом `setChatMenuButton` и открывает тот же Mini App, что inline-кнопка. Прямая ссылка `https://t.me/botusername?startapp` и `startapp` передают значение в `start_param` и в GET-параметр `tgWebAppStartParam`. Этот параметр не является правом.
- Клиент подключает `https://telegram.org/js/telegram-web-app.js` и получает `window.Telegram.WebApp`. Поле `initData` — сырая строка для проверки на сервере. Поле `initDataUnsafe` прямо помечено как недоверенное: его нельзя считать личностью.
- Проверка ботом: убрать `hash`, собрать остальные поля в алфавитном порядке через перевод строки `key=value`, секрет — HMAC-SHA256 токена бота с ключом `WebAppData`, затем hex HMAC-SHA256 этой строки. Сравнение с `hash`. `auth_date` — unix-время открытия, его проверяют отдельно, чтобы отсечь устаревшие данные. Поле `signature` — отдельная подпись Ed25519 для третьей стороны без токена бота. Публичные ключи со страницы: test `40055058a4ee38156a06562e52eece92a771bcd8346a8c4615cb7376eddf72ec`, production `e7bf03a2fa4602af4580703d88dda5bb59f32ed8b02a56c187fe7d34caed242d`. StarFlow проверяет `hash` своим токеном и не принимает третью сторону вместо этой проверки.
- `viewportHeight` обновляется во время жеста и не годится, чтобы прижимать элементы к низу. Для этого указан `viewportStableHeight` и CSS `var(--tg-viewport-stable-height)`. Событие `viewportChanged` с `isStateStable=true` отмечает конец анимации.
- `safeAreaInset` и `contentSafeAreaInset` доступны полями и CSS-переменными `--tg-safe-area-inset-*` и `--tg-content-safe-area-inset-*`. События `safeAreaChanged` и `contentSafeAreaChanged` приходят с Bot API 8.0.
- `BackButton` с Bot API 6.1: `show`, `hide`, `onClick`, `offClick`. `enableClosingConfirmation` с Bot API 6.2 показывает системный диалог при закрытии Mini App. Оба метода есть не в каждой версии клиента, поэтому вызов идёт только если метод есть.
- `WebAppInitData` пустой, если Mini App открыт с клавиатурной кнопки или из inline mode. Для кнопки `web_app` у inline-клавиатуры и menu button данные пользователя приходят.

Решение. Обёртка клиента читает только `initData` и методы интерфейса. `initDataUnsafe` в код приложения не входит. Сервер проверяет `hash` постоянным по времени сравнением и окно `auth_date`.

Причины. Так страница описывает единственный способ считать пользователя известным.

Альтернативы. Доверять `initDataUnsafe` в WebView. Проверять только Ed25519 `signature` и не использовать токен бота.

Последствия. Обёртка молчит вне Telegram. Живой клиент Telegram этой сессией не прогонялся: проверялись текст документации и локальные HMAC-тесты.

## D-026. Короткая серверная сессия в cookie

Контекст. Ранний контракт слал `Authorization: TMA <initData>` на каждый запрос. Нужна короткая сессия после одной проверки, без одноразовости, которая ломает повторные запросы и повторное открытие.

Решение. `POST /api/v1/session` один раз принимает `initData` в заголовке `Authorization`, не в URL. Ответ ставит cookie `starflow_session`: `HttpOnly`, `SameSite=Strict`, `Path=/`, `Secure` только при `APP_ENV=production`. В базе лежит SHA-256 токена и `expires_at`. Срок cookie — `SESSION_TTL_SEC`, по умолчанию 3600 секунд. Тело ответа токен не содержит. Дальнейшие запросы опознают пользователя только по этой cookie. `user_id` из тела и URL не читается.

`initData` в пределах `AUTH_MAX_AGE_SEC` и будущего сдвига `AUTH_FUTURE_SKEW_SEC` можно обменять повторно: новая сессия не гасит предыдущую и не помечает подпись использованной. Сам токен тоже многоразовый до срока или `POST /api/v1/session/logout`. Logout помечает строку отозванной и очищает cookie.

CSRF: `SameSite=Strict` не отправляет cookie на чужой сайт. Изменяющие запросы дополнительно требуют заголовок `X-Starflow-Request: 1`, который чужая страница не поставит без CORS. CORS с `allow_credentials` включается только для явного списка `ALLOWED_ORIGINS` и не использует `*`. Заголовок `Authorization` и cookie не пишутся в журнал. XSS не читает `HttpOnly` cookie; `initData` не кладётся в `localStorage`.

Причины. Mini App и API живут на одном origin, поэтому cookie первого лица здесь уместнее, чем токен в JavaScript. Короткий срок ограничивает украденную cookie, а повторное использование `initData` совпадает с тем, как Telegram держит одну строку на время жизни WebView.

Альтернативы. Слать сырой `initData` на каждый запрос. Хранить bearer в `localStorage`. Делать `initData` одноразовым.

Последствия. Пункт conventions про заголовок `TMA` на каждом запросе заменён обменом один раз и cookie дальше. Тесты ходят с cookie и заголовком намерения.

## D-027. Dev-auth только локально

Контекст. Вне Telegram нужен понятный экран, а локальной разработке иногда нужен вход без подписи. В production такой вход недопустим.

Решение. `DEV_AUTH_ENABLED=true` принимается только вместе с `APP_ENV=local`. При `APP_ENV=production` процесс не стартует, если флаг включён. `APP_ENV=test` флаг игнорирует и принимает только настоящий HMAC. Вход — `POST /api/v1/session/dev` с заголовком `X-Starflow-Dev-User`. Сборка frontend не содержит мост, который подделывает Telegram. Мост живёт в Playwright и подставляется только тестовым браузером.

Причины. Нельзя случайно выкатить обход подписи. Тесты подписи не должны зависеть от обхода.

Альтернативы. Общий тестовый пользователь в production. Флаг без проверки окружения.

Последствия. Экран вне Telegram не предлагает dev-вход. Playwright описывает мост в своём тесте, не в приложении.

## D-028. Черновик профиля и стартовый параметр

Контекст. Онбординг прерывается закрытием Mini App. Стартовый параметр реферала или подарка приходит раньше, чем появятся права.

Решение. Шаги `welcome`, `name`, `date`, `time`, `timezone`, `place`, `done` хранятся в `profiles.onboarding_step`. Пока шаг не `done`, имя и пояс могут быть пустыми. Клиент не выбирает шаг: сервер применяет поле текущего шага или отходит назад. Место рождения сохраняется только для активного premium и только если координаты есть в кэше геокодера по этому запросу. Пояс после подтверждения места считает `timezonefinder` без сети. Стартовый параметр длиной до 64 символов из `A-Za-z0-9_-` пишется в `users.pending_start_param` и не открывает период, подарок или реферальную награду.

Причины. Черновик на сервере переживает закрытие WebView. Параметр из ссылки — это навигация и заявка, не право.

Альтернативы. Хранить черновик в `localStorage`. Сразу начислять подарок из `start`.

Последствия. Онбординг в чате бота не проводится. Команды бота открывают готовый экран Mini App или, для удаления, просят одно подтверждение.

## D-029. Знак на главной — календарная подпись, не эфемерида

Контекст. После онбординга нужен знак, а `pyswisseph` ещё не подключён и лицензия не выбрана.

Решение. Знак считается по календарным границам тропического круга от даты рождения. Это подпись экрана, не положение Солнца и не натальная карта. Расчёт долготы остаётся в `sign_for_longitude` и по-прежнему не вызывается как карта.

Причины. Дата уже есть после онбординга. Выдумывать эфемериду нельзя.

Альтернативы. Не показывать знак до среза эфемерид. Подставить фиксированный знак.

Последствия. Текст рядом называет материал развлекательным. Когда появится эфемерида, календарная подпись не станет источником карты.

## D-030. Тексты frontend из тех же YAML

Контекст. Conventions когда-то делили строки на `ru.ts` и серверные ресурсы. Каркас уже держит авторские строки в `resources/texts/ru`.

Решение. YAML остаётся единственным источником. Сборка запускает `frontend/scripts/compile-texts.mjs` и пишет `frontend/src/generated/texts.ts`. `pnpm texts:check` сравнивает файл с повторной генерацией. Плейсхолдеры `{name}` подставляются без смены регистра значения. Русская плюрализация выбирает форму `one`, `few` или `many`.

Причины. Две ручные копии расходятся. Генерация проверяется так же, как OpenAPI.

Альтернативы. Поддерживать `ru.ts` руками.

Последствия. Новая строка добавляется в YAML и попадает в клиент после генерации. Серверный каталог читает тот же файл.

## D-031. Лимиты живут в правиле функции, не в имени тарифа

Контекст. `idea.md` называет бесплатное избранное 30, а этот срез прямо задаёт не больше 3 активных записей. Совместимость — 1 на местную неделю, помощник — 20 на оплаченный период. Ветки `if plan == "premium"` разъедутся с YAML.

Решение. `resources/plans.yaml` описывает каждую функцию: `gate` (`open`, `metered`, `capacity`, `premium`), числовой `limit` и окно `user_week` или `paid_period`. `QuotaService` читает это правило. Бесплатный предел избранного в YAML — 3, и он заменяет стартовые 30 из `idea.md`, пока YAML снова не изменят. Числа в секции `free` и `premium` совпадают с правилами функций, загрузчик это проверяет.

Причины. Смена лимита не требует ветки в сервисе. Имя тарифа не становится вторым источником правды.

Альтернативы. Оставить 30 и игнорировать текущую постановку. Хранить лимиты только в коде.

Последствия. Избранное сверх трёх активных записей отклоняется. Premium не увеличивает этот предел, пока в правиле `favorite` нет отдельного числа.

## D-032. Расчёт на pyswisseph и модели Мошье

Контекст. 2026-10-21 сверены [условия Swiss Ephemeris](https://www.astro.com/swisseph/swephinfo_e.htm) и `LICENSE` репозитория swisseph: двойная лицензия AGPL-3.0 или профессиональная лицензия Astrodienst. Выбор по-прежнему не сделан, поэтому публичный сервис не готов. Колёса `pyswisseph` не содержат файлы `sepl_18.se1`, `semo_18.se1`, `seas_18.se1`. Без них библиотека умеет встроенную теорию Стива Мошье: лучше 0.1″ для планет и около 3″ для Луны, диапазон примерно 3000 до н.э. — 3000 н.э.

Решение. Порт `Ephemeris` реализован на `pyswisseph` с явным флагом `FLG_MOSEPH`. Файлы `.se1` не скачиваются при старте и не подкладываются в образ. `kerykeion` не подключается. Календарная таблица солнечного знака остаётся для одной даты. Долгота Солнца из эфемериды используется только когда есть дата, однозначное местное время и подтверждённое место.

Причины. Образ воспроизводим из lock-файла без сети в рантайме. Молчаливый поиск `.se1` сделал бы результат зависящим от машины.

Альтернативы. Вендорить 97 МБ сжатых эфемерид. Считать только календарём. Принять AGPL на весь репозиторий без отдельной записи владельца.

Последствия. Точность Луны — модель Мошье, не DE441. Публичный запуск закрыт, пока нет выбора лицензии. Имена Astrodienst в интерфейсе не используются. Стадия `python-deps` ставит `gcc`, `g++` и `libc6-dev`, потому что lock содержит только sdist и сборка зовёт `g++`; рантайм-стадия забирает собранное расширение и компилятор не оставляет.

## D-033. Дома, орбисы, деканы, лунный день и местное время

Контекст. Нужно явно зафиксировать то, что иначе остаётся негласным правилом расчёта.

Решение. Дома — Плацидус (`P`). Они и асцендент считаются только при известных координатах и однозначном местном времени. Орбисы мажорных аспектов: соединение 8°, оппозиция 8°, квадрат 6°, трин 6°, секстиль 4°. Декан — 10° внутри знака, управители в халдейском порядке, Овен начинает с Марса. Лунный день — номер местного восхода Луны, начиная с 1 на восходе после точного новолуния. Без координат поле пустое. Местное время в пропуске перевода часов или в перекрытии (fold) не приводится к одному мгновению: углы и точный лунный знак не создаются. Неизвестное время хранится пустым; планеты для справки считаются на местный полдень, точный лунный знак и дома не выдаются.

Причины. Выбрать один из двух моментов перевода часов значило бы выдумать асцендент. Полдень без пометки тоже не является временем рождения.

Альтернативы. Всегда брать более ранний fold. Солнечные дома без времени. Лунный день как целые сутки от новолуния без восхода.

Последствия. Экран пишет, какого сведения нет. Смена даты, времени, места или пояса меняет отпечаток карты, и снимок пересчитывается.

## D-034. Квота резервируется и списывается после выдачи

Контекст. Повтор HTTP-запроса и конкурентный запрос не должны списывать лимит дважды или пропускать лишний расчёт. Отказ и ошибка не должны съедать попытку. Проверка paywall не должна менять счётчик.

Решение. `QuotaService` — единственная точка. Результат: `Allowed`, `LimitReached(reset_at)` или `PremiumRequired`. Для счетных функций строка счётчика блокируется `FOR UPDATE`. `reserve` увеличивает `reserved`, `commit` переносит резерв в `used` вместе с сохранённым результатом, `release` снимает резерв. Успех выдачи Mini App — это запись результата в той же транзакции, что и `commit`. Пока записи нет, лимит не потрачен. Ключ `Idempotency-Key` уникален на пользователя: повтор после `committed` возвращает сохранённое тело и не резервирует снова. `preview` только читает. Ёмкость избранного считает активные строки под блокировкой пользователя. Неделя совместимости начинается в понедельник 00:00 в поясе профиля. Вопросы помощника привязаны к интервалу оплаченного источника, не к календарному месяцу. Grace рекуррентной подписки продлевает доступ отдельным `grace_until` и не открывает новый пакет вопросов.

Причины. Списание до ответа теряет попытку на ошибке сети. Проверка «можно ли» не должна быть расходом.

Альтернативы. Списывать в начале запроса. Считать идемпотентность только на клиенте.

Последствия. Зависший резерв после гибели процесса держит слот, пока строка не снята. Один worker уменьшает окно такой гонки, но не заменяет `release` в `finally`.

## D-035. Файлы Google Sans лежат в `static/font`

Контекст. D-006 требовал самохостинг семейства `Google Sans` и сверку copyright внутри файла с `OFL.txt`. Согласованный ранее каталог `frontend/src/assets/fonts/` пуст: файлы положены в `static/font`.

Проверка 2026-10-21. Таблица `name` обоих файлов: семейство `Google Sans`, версия `13.002`, copyright `Copyright 2025 The Google Sans Project Authors (github.com/googlefonts/googlesans)`, лицензия SIL OFL 1.1. Ось `wght` — 400–700, ось `opsz` — 17–18. Сопровождающий `OFL.txt` из каталога `ofl/googlesans` начинается с `Copyright 2025 The Google Sans Project Authors`. Это та же редакция, что в бинарнике.

Решение. Файлы остаются в `static/font` вместе с `OFL.txt` и `TRADEMARKS.md`. `@font-face` называет семейство `Google Sans`, `font-display: block`, вес 400–700, прямое начертание и курсив отдельными файлами. Сборка frontend кладёт начертания в `frontend/dist`. Образ копирует каталог в `/app/static/font`, чтобы лицензия была читаема рядом с файлами. Загрузка с серверов Google не используется.

Причины. Перекладывать уже добавленные файлы в другой каталог ничего не меняет в шрифте. Лицензия должна ехать вместе с бинарником.

Альтернативы. Оставить только имя в CSS и `sans-serif`. Перенести файлы в `frontend/src/assets/fonts/`.

Последствия. `sans-serif` остаётся вторым именем каскада. Товарный знак Google в названии продукта и в текстах страниц не используется.

## D-036. Главный экран — плитки, пояс берётся с устройства

Контекст. После просмотра Mini App шаги онбординга и главный экран оказались лишними: кружок на каждой кнопке, вопрос про часовой пояс, кнопка «проверить связь» и список ссылок.

Решение. Кнопки действий содержат только подпись. Радиус `999px` остаётся у кнопок форм. Главный экран — сетка из двух квадратных плиток в ряд: знак SVG со штрихом 1.5 и подпись из ресурса. Справа сверху круглый переход в профиль, где редактируются имя, дата и время рождения. Пока открывается сессия или карта, по центру экрана логотип и строка «загрузка». Часовой пояс не спрашивается: при сохранении времени рождения клиент передаёт пояс устройства, а если его нет — `Europe/Moscow`. Подтверждённое место по-прежнему записывает пояс координат. Старый шаг `timezone` в базе допустим и при открытии сразу уходит дальше без экрана.

Причины. Пояс устройства уже есть у телефона. Отдельный вопрос и проверка связи не помогают выбрать разбор. Плитка с рисунком читается быстрее строки-ссылки.

Альтернативы. Оставить пояс ручным полем. Нарисовать на плитках emoji. Emoji в авторских текстах страниц по-прежнему запрещены, поэтому знак плитки — SVG.

Последствия. Черновик, который остановился на шаге `timezone`, не показывает этот вопрос. Смена места рождения по-прежнему пересчитывает пояс.

## D-037. Сообщение боту открывает приложение кнопкой

Контекст. На произвольный текст бот отвечал, что адрес приложения не задан. Нужен способ открыть Mini App из чата.

Решение. Любой текст и команды экранов, если задан `MINI_APP_URL`, отвечают коротким текстом и кнопкой `web_app`. Нажатие открывает Mini App. Без адреса та же реплика объясняет, где эта кнопка будет: под сообщением и слева от поля ввода. Самостоятельно открыть клиент Telegram из ответа бота нельзя: нужен жест пользователя и https-адрес.

Причины. Bot API не даёт событие «открыть Mini App» без кнопки. Кнопка `web_app` — штатный способ.

Альтернативы. Молчать на произвольный текст. Оставить фразу «напишите позже».

Последствия. Пока `MINI_APP_URL` пуст, кнопки нет и в ответе это сказано. `http://127.0.0.1` для этой кнопки не годится.

## D-038. Главный экран без статичного текста, знаки — emoji

Контекст. После плиток сверху остались имя, знак и пояснение. На телефоне кнопка Close перекрывает шапку. Силуэты на плитках читаются хуже цветных знаков. В профиле отдельная кнопка «не знаю» лишняя.

Решение. На главном экране остаётся одна короткая фраза из десяти, они сменяются по кругу с затуханием. Случайный старт, затем порядок по списку. Слева шарик со знаком зодиака, справа шарик профиля. На плитках и в шарике знака — цветные emoji (`Apple Color Emoji` на iPhone), подписи плиток остаются текстом из ресурса. Верхний отступ страницы не меньше 52px, чтобы не залезать под Close, и растёт вместе с `--tg-content-safe-area-inset-top`. Загрузка: логотип плавно меняет масштаб, у слова «загрузка» по очереди одна, две и три точки. Пустое время рождения в профиле сохраняется как неизвестное, без кнопки «не знаю». При `prefers-reduced-motion` смена фразы, пульс логотипа и точки не крутятся.

Причины. Фраза задаёт тон без анкеты на главном экране. Цветной знак зодиака узнаётся сразу. Close в Telegram рисуется поверх страницы, если верхний inset нулевой.

Альтернативы. Оставить svg-силуэты. Держать дисклеймер отдельной строкой на главном. Кнопка «не знаю» в профиле.

Последствия. Дисклеймер остаётся на экране карты. Десять фраз не обещают точное событие. Онбординг по-прежнему спрашивает «не знаю» отдельной кнопкой.

## D-039. Свайп назад, плашка только на главной, знак в капсуле профиля

Контекст. С главного экрана уходят на карту, профиль и справки. Кнопка «назад» есть, жеста от края нет. Плашка «развлекательный материал» стояла на карте. Круг знака слева отдельно от круга профиля. «удалить данные» была в одном ряду с «сохранить».

Решение. Жест от левого края вправо на 80px возвращает предыдущий экран приложения. Если экран открыт напрямую, жест ведёт на главную. На главной жест ничего не закрывает. Плашка развлекательного материала убрана с карты и остальных экранов и стоит внизу главной: 12px, цвет `#b8b8b8`. Экран «условия» оставляет свою фразу. Знак зодиака без своего круга стоит в серой капсуле справа, слева от белого круга профиля. Капсула — `#b8b8b8`. «удалить данные» прижата к низу профиля: белая заливка, обводка и текст `#9b2d30`. При наведении и при нажатии заливка становится `#9b2d30`, текст `#f5f0f0`.

Причины. Жест совпадает с привычкой iOS и не должен закрывать Mini App с главной. Плашка на каждом расчёте занимала место; напоминание остаётся на входе и в условиях. Знак и профиль читаются как одна шапка. Удаление отделено от сохранения и выглядит обратимым, пока палец не наведён.

Альтернативы. Оставить плашку на карте. Вернуть круг знака слева. Красить «удалить данные» красной заливкой сразу.

Последствия. Вторичный цвет на этой строке слабее основного: контраст `#b8b8b8` на `#f5f0f0` по-прежнему 1.757:1, WCAG не заявляется. Условия по-прежнему говорят, что разбор не обещает точных событий.

## D-040. Общий текст сегмента и вызов модели вне транзакции

Контекст. Бесплатный день, неделя, совет, луна и совместимость должны звучать живым текстом, но один и тот же сегмент не должен платить моделью за каждого пользователя. Первый попавшийся профиль нельзя класть в общий ключ: в нём точные дата, время и место.

Решение. Ключ кэша — `forecast_type`, `period_key`, `segment`, `topic`, `locale`, `prompt_version`. Период считается в `DEFAULT_TIMEZONE`: дата, ISO-неделя или месяц. Сегмент бесплатного дня, недели и совета — только солнечный знак. Подробные сегодня и завтра — солнце, луна и декан общего неба этой даты. Персональный и тематический сегмент — солнце, луна и асцендент либо `unknown`. Совместимость — отсортированная пара знаков. Луна — дата. Натальная карта — хеш округлённых знаков планет, домов и аспектов. Синастрия — отсортированная пара нормализованных профилей. Календарь — солнце, луна, асцендент и месяц. Чат не кэшируется. В промпт уходят только эти репрезентативные факты. Имя и обращение подставляются после чтения кэша и в общий JSON не пишутся. Свой знак пользователя показывается отдельной строкой.

`AsyncOpenAI` создаётся с `max_retries=0`. Повторы 429, 5xx и таймаута делает один цикл с экспоненциальной паузой и дрожанием. Пять неудачных вызовов подряд открывают предохранитель на 30 секунд. JSON-режим — `json_object` по справочнику DeepSeek; это не schema enforcement. Ответ проверяет Pydantic. Один ремонтный запрос, затем строка из ресурса и одна фоновая попытка на ключ. `OutputGuard` оставляет простой текст: без HTML, markdown и emoji. Регистр с D-051 не меняется. Ответ модели не исполняется. Telegram-рендер отдельно экранирует HTML и режет текст до 4096, не разрывая сущность.

L1 — ограниченный TTL LRU в памяти процесса. L2 — `forecast_cache`: JSONB, `valid_until` как срок, `hits`. Срок L1 равен сроку строки L2 и не длиннее его. День живёт до конца местных суток плюс 6 часов, неделя до следующего понедельника, месяц до следующего месяца, натал — до смены `prompt_version`. На один ключ есть `asyncio.Lock` и `pg_advisory_xact_lock(hashtext(key))`. Внешний вызов модели идёт после коммита этой короткой транзакции. Повторная проверка кэша — уже в новой транзакции перед записью. Отмена снимает lock и не пишет частичный JSON. Пул соединений остаётся явным: `pool_size=5`, `max_overflow=10`. Держать соединение на время ответа модели нельзя: пять таких запросов заняли бы весь пул.

Выдача в Mini App не ждёт модель в HTTP-запросе. `POST /readings/{kind}` с `Idempotency-Key` сразу возвращает `pending`, `ready`, `fallback` или `error`. Тот же ключ возвращает тот же итог. Клиент опрашивает `GET`, пока статус не перестанет быть `pending`. Попадание в кэш увеличивает `hits` и не пишет строку `ai_requests`. Строка `ai_requests` появляется только у настоящего вызова: модель, токены, длительность, вид прогноза, исход или код ошибки. Ошибка модели не списывает квоту совместимости.

Причины. Общий сегмент дешевле и не утекает первым профилем. Точность ниже персональной карты: два козерога читают один дневной текст, а не разбор своего часа рождения. Короткий замок не занимает соединение на десятки секунд. Опрос переживает обрыв и повтор HTTP.

Альтернативы. Кэшировать полный профиль первого пользователя. Держать транзакцию открытой на время модели. Отдавать текст одним длинным POST.

Последствия. Персональная натальная карта по-прежнему считается отдельно и не подменяется этим общим текстом. Награда реферала по-прежнему ждёт подтверждённый платёж: сейчас выдаётся только код и ссылка без токена. Публичный запуск модели не заявляется без ключа DeepSeek.

## D-041. Шапка по центру, смена фразы раз в десять секунд

Контекст. Слово «загрузка» стояло левее логотипа: строка была выровнена влево, чтобы точки не прыгали. Фразы сменялись за 3.8 с коротким сдвигом. Капсула знака и профиля была прижата вправо, тип подписки в ней не читался.

Решение. Слово «загрузка» стоит по центру экрана, как логотип. Точки висят справа от слова и ширину строки не меняют. Фраза на главной держится 10 секунд, затем уходит и приходит за 1.4 с со сдвигом на 6px. Капсула `#b8b8b8` стоит по центру шапки. Внутри слева направо: emoji знака, белый круг профиля, отметка подписки. Бесплатный план — emoji 🆓, premium — ✨. Подписи для чтения с экрана: «бесплатная» и «premium». При `prefers-reduced-motion` фраза не сменяется, загрузка не пульсирует.

Причины. Центр загрузки совпадает с центром логотипа. Десять секунд дают прочитать фразу. Капсула собирает знак, профиль и план в одну строку и не прячется под кнопку Close.

Альтернативы. Оставить капсулу справа. Писать слово free строчными в ресурсе вместо emoji отметки.

Последствия. Отметка плана — emoji, как знак и плитки. Авторский текст страниц по-прежнему без emoji. Контраст серой капсулы не меняется, WCAG не заявляется.

## D-042. Стартовый экран и анкета без карточки

Контекст. После входа сразу открывалось «добро пожаловать» внутри белой карточки. На шаге имени заголовок и подпись поля повторяли одну фразу. Дата требовала точки с клавиатуры. На времени оставалась кнопка «не знаю», на грязном черновике — «отмена».

Решение. Пока шаг `welcome` и человек не нажал «начать», экран — логотип, кнопка «начать» по центру и внизу те же десять фраз серым `#b8b8b8`, со сменой раз в 10 секунд. Дальше анкета без карточки: блок по вертикали в центре экрана, текст слева. Заголовок имени — «как к вам обращаться?», второй подписи нет. «отмена» убрана со всех экранов. В дате пользователь вводит только цифры, точки ставятся после второй и четвёртой. Пустое время рождения на этом шаге сохраняется как неизвестное, без кнопки «не знаю».

Причины. Первый экран задаёт вход, не анкету. Карточка сужала текст. Повтор подписи и ручные точки мешали вводу. Пустое время уже означает неизвестное в профиле.

Альтернативы. Оставить «не знаю» и «отмена». Центрировать строки анкеты.

Последствия. Серые фразы на старте не единственное действие: кнопка «начать» остаётся основным цветом. Контраст `#b8b8b8` на `#f5f0f0` по-прежнему 1.757:1, WCAG не заявляется. Кнопка «не знаю» в онбординге больше не показывается.

## D-043. Stars: invoice link, успешный платёж и границы Bot API

Контекст. Premium, подарок и пробный период должны открываться из Mini App. Клиент умеет закрыть счёт и получить строку статуса. Этого недостаточно, чтобы выдать доступ. Нужно опереться только на методы, которые есть в актуальной документации Telegram, и не обещать атомарность между Bot API и PostgreSQL.

Решение. Покупка идёт так: защищённый `POST /api/v1/billing/orders` создаёт заказ и вызывает `createInvoiceLink`. Mini App открывает ссылку через `WebApp.openInvoice` (Bot API 6.1+). Событие `invoiceClosed` отдаёт статус `paid`, `cancelled`, `failed` или `pending`. Эти строки только показывают состояние экрана. Доступ меняет только `successful_payment`, после `pre_checkout_query`, на который бот отвечает быстрее 10 секунд.

Рекуррентные Stars для Mini App есть с Bot API 8.0: тот же `createInvoiceLink` с `currency=XTR`, ровно одним `LabeledPrice`, `provider_token=""` и `subscription_period=2592000`. Другого периода документация не разрешает, отдельного метода подписки у Mini App нет. Цена — 1..10000 Stars и совпадает с `plans.yaml`. Чаевые, имя, телефон, почта и доставка для Stars не используются. `payload` — идентификатор заказа и HMAC, не длиннее 128 байт. Журнал изменений 7.4 просил опускать `provider_token`; текущая страница метода просит пустую строку. Код передаёт пустую строку и не держит второй вариант.

`SuccessfulPayment` хранит `telegram_payment_charge_id`, `subscription_expiration_date`, `is_recurring` и `is_first_recurring`. Повтор того же charge id не удлиняет период. Следующее списание того же заказа — новый charge id и новый период. Для `editUserStarSubscription` сохраняется `telegram_payment_charge_id` первого списания. `is_canceled=true` останавливает продление, доступ живёт до конца оплаченного периода. `is_canceled=false` только позволяет человеку снова включить подписку, которую отменил бот. Само продление от этого вызова не запускается.

`refundStarPayment` принимает `user_id` и `telegram_payment_charge_id`. Страница метода не говорит, что возврат отменяет продление, поэтому возврат не вызывает `editUserStarSubscription`. Отзывается только допуск, связанный с этим списанием. Подарок, пробный период, реферал, админская выдача и другие списания остаются. Вызов Telegram и коммит базы — разные шаги: сначала намерение (`cancel_pending`, `resume_pending`, `refund_pending`), потом вызов, потом локальное подтверждение. Если процесс оборвался между ними, задание раз в 10 минут повторяет вызов. Распределённая транзакция не заявляется.

Пробный период один на пользователя, срок в `plans.yaml`. Подарок — разовый счёт XTR без `subscription_period`. Тридцать дней доступа начинаются в момент одноразового погашения кода, не в момент оплаты. Код случайный, сравнение не пишет его в журнал, восемь ошибок за час останавливают попытки. Погашение — один `UPDATE` строки со статусом `issued`. Себе код не активируется. Реферальные дни и админская выдача пишутся отдельным источником и не выглядят как платёж Telegram.

Час grace — только задержка рекуррентного списания у неотменённой подписки. Три дня — напоминание об уже отменённой подписке, а не дополнительный доступ. Прежний `grace_days: 3` больше не продлевает допуск. Напоминание одно на дату окончания за счёт уникального outbox.

Причины. Mini App не подтверждает деньги. Повторная доставка update и вторая вкладка не должны удваивать срок или терять чужой допуск. Документированные пределы Telegram лучше зафиксировать, чем подбирать соседний метод.

Альтернативы. Считать `openInvoice: paid` оплатой. Слать `sendInvoice` в личный чат. Выдумывать другой `subscription_period`, пробный период Telegram или атомарный коммит вместе с Bot API.

Последствия. Живой платёж Stars этим решением не проверялся. Ручной чек-лист лежит в `docs/PAYMENTS.md`. Пока его не прошли в Telegram, оплата не считается проверенной на боевом боте.

## D-044. Типографический альманах вместо плиток

Контекст. Главный экран был сеткой плиток с emoji, капсулой знака и серой отметкой плана. Макет «вариант 02 — альманах» задаёт другую композицию: крупное число дня, винный блок, редакционный список и нижнюю навигацию. Тёмная тема в прежних правилах не была описана.

Решение. Светлый альманах — основной вид. Эталонные экраны: главная, календарь, premium. Остальные экраны используют те же токены, разделители и pill-кнопки. Плитки, капсула и emoji знака с главного экрана уходят. Нижняя навигация: сегодня, календарь, близкие, профиль. Иконки — SVG из `static/icons/svg`. Иллюстрация premium — `static/illustrations/three-circles-cream.svg` на винном поле. Выбор темы хранится в `localStorage` ключом `starflow-theme`: `light`, `dark` или `telegram`.

Причины. Макет читается как редакционная страница, а не как набор карточек. Общие токены не дают страницам разойтись. Готовые файлы в `static` не нужно рисовать заново.

Альтернативы. Оставить плитки и натянуть на них новые цвета. Собрать три окружности заново из CSS.

Последствия. Визуальные части D-036, D-038 и капсула из D-039 и D-041 для главного экрана больше не действуют. Стартовый экран и анкета из D-042 остаются. Файл трёх окружностей в `static` — горизонтальный ряд, не треугольник. Отдельных файлов дуги, маркеров шкалы и иконки «сегодня» в `static` нет: навигация «сегодня» использует `sun.svg`, дуга и маркеры — геометрия компонента. Живой снимок макета в репозиторий не клался.

## D-045. Premium-разборы, календарь, синастрия и диалог

Контекст. D-040 уже задал ключ сегмента и запрет кэшировать чат. D-013 и D-034 задали квоту в той же транзакции, что и сохранённый результат. Оставалось выбрать темы, проверку JSON календаря, согласие на данные близкого и границу диалога.

Решение. Темы — «отношения», «работа», «финансы», «эмоциональное состояние». Подробные сегодня и завтра читают солнце, луну и декан неба этой даты; без долготы декан остаётся `unknown`. Персональные день, неделя, месяц, темы и календарь берут луну и асцендент только из доступной карты. Нет времени или места — домов и асцендента нет, в тексте стоит `unknown`. Разделы карты строятся из уже посчитанных полей; подписи остаются рядом с обозначениями. Графика карты не обязательна.

Календарь месяца принимается только если JSON содержит каждый реальный день этого месяца, оценки 1–5 по четырём темам и не содержит чужих или повторных дней. Февраль високосного года — 29 дней, обычного — 28. Один ремонтный запрос. Всё ещё негодный JSON даёт запасной текст без дней и не становится платным результатом.

Синастрия считается по двум профилям. Пара в ключе кэша нормализуется и сортируется. Ограничения неполных данных дописываются уже после общего текста и остаются у пользователя. Согласие на хранение близкого отдельно от бесплатной совместимости: без него синастрия не строится. Удаление снимает строку близкого.

Помощник получает системный текст из файла, отдельным сообщением факты профиля и последние 8 реплик. Вопрос пользователя — последнее сообщение роли `user`, не склейка с system. Длина вопроса — до 500 символов, бюджет контекста — 1500 токенов по оценке символов. Введённый текст хранится как введён. Ответ модели проходит обычную очистку. Классификация off-topic и injection смотрит пересечение категорий слов, а не один regex. Такой отказ сохраняется без списания квоты и без вызова модели. У модели нет инструментов. Фильтр не обещает остановить любую подмену инструкции. Успешный ответ списывает одну из 20 попыток периода подписки. Негодный JSON один раз чинится; повторная негодность снимает резерв и не списывает попытку. Чат не кэшируется.

`QuotaService` остаётся единственной точкой допуска. `hold` резервирует, `finish` пишет результат и списывает только при `charge=true`, `release_hold` снимает резерв. Тот же `Idempotency-Key` возвращает сохранённый итог, в том числе отказ. Новый ключ не наследует чужой отказ, ошибку или запасной текст и может посчитать разбор заново. Готовый текст периода отдаётся без второго вызова модели. Результат пишется до ответа клиенту.

Причины. Общий сегмент не должен выдумывать дома. Календарь с лишним днём нельзя показывать как месяц. Данные близкого без согласия не должны попадать в разбор. Отказ и битый JSON не должны съедать оплаченный вопрос. Повтор кнопки не должен запускать вторую генерацию.

Альтернативы. Считать regex достаточной защитой. Кэшировать диалог. Склеивать вопрос с system. Обещать, что фильтр закрывает все prompt injection.

Последствия. Живой DeepSeek этим решением не вызывался. Ретроспектива в срез не входит. Публичный запуск по-прежнему закрыт до лицензии Swiss Ephemeris. Живой чек-лист Stars не пройден.

## D-046. Уведомления, прогрев, станции и страница админа

Контекст. D-001 держит один worker и одну реплику. D-020 уже кладёт доставку в `notification_outbox`. D-014 описывает удаление учётной записи. Нужны местное время, аренда строки, прогрев общего кэша, станции Меркурия, Венеры и Марса, реферальная награда, streak, сводка для `ADMIN_IDS` и явная политика того, что остаётся после удаления.

Решение. Планировщик — APScheduler 3 в том же процессе. У заданий `max_instances=1`, `coalesce=True`, `misfire_grace_time=60`. Остановка ждёт текущее задание. Повторный процесс по-прежнему упирается в один worker и advisory lock; уникальный ключ outbox и `FOR UPDATE SKIP LOCKED` не дают второй доставке забрать ту же свободную строку.

Слот — `HH:MM`, минуты только 00 или 30, часовой пояс хранится как введён. Раз в минуту выбираются местные даты, у которых слот уже наступил и с него прошло меньше трёх часов. Весенний разрыв: если выбранные часы не существуют, досылка начинается с первой существующей минуты после разрыва. Осенний повтор часа не создаёт второе событие: ключ — календарная дата, не fold. Виды включаются отдельно: день, луна, premium-ретро. Старый `digest_enabled` сам по себе эти виды не включает.

Захват — один `UPDATE … RETURNING` по строкам `FOR UPDATE SKIP LOCKED`. Статус аренды — `reserved`, срок две минуты. `sent` ставится только после ответа отправки. Ошибка, `RetryAfter` и `Forbidden` не помечают строку отправленной. `Forbidden` ставит `is_blocked`. Обрыв после send и до commit может доставить то же сообщение ещё раз, когда аренда истечёт. Exactly-once не обещается.

Очередь в процессе держит около 25 сообщений в секунду. Текст короткий, кнопка открывает страницу Mini App. Рассылка читает только кэш. Промах даёт запасную фразу и не вызывает модель. Прогрев идёт в `DEFAULT_TIMEZONE` с 05:00 до 08:00: 12 знаков и луна каждое утро этого окна, 78 неупорядоченных пар с повторениями только в понедельник внутри окна. Если процесс пропустил весь понедельничный интервал, пары ждут следующего понедельника. Параллельность 3, бюджет 20 вызовов модели на запуск, один повтор негодного JSON. Модель берётся по tier промпта. Общий ключ считается в `DEFAULT_TIMEZONE`, дата события — в поясе человека.

Станция — первый час, где скорость уже отрицательная. Поиск локальный, теория Мошье, шаг 12 часов, точность бисекции один час. Это не ежегодник и не обещание события. Premium получает одно событие за три дня и одно в день начала. Ключ события — планета, дата станции в `DEFAULT_TIMEZONE` и фаза.

Реферал связывается только со стартовым параметром `ref_` и существующим кодом. Сам на себя и повторная атрибуция не проходят. Награда из `plans.yaml` — семь дней, источник `referral`, один раз после первого списания подписки приглашённого. Streak растёт по местной дате открытия прогноза дня: тот же день не увеличивает, вчера увеличивает, пропуск сбрасывает к одному.

Сводка админа — интервал дат включительно, граница суток UTC, не длиннее 366 дней. По умолчанию последние 30 суток. Считает людей с прогнозом, открытые учётные записи, платежи, звёзды, возвраты, источники premium, модели, токены, ошибки, медиану latency, строки и hits кэша за интервал, оценки по виду прогноза и версии промпта. Счётчики L1 и генераций — этого процесса. Имён, дат рождения, текстов переписки и комментариев нет. Выдача периода и возврат требуют подтверждение и пишут аудит. Команды бота `/stats`, `/cache_stats` и `/refund` короче страницы и её не заменяют. Неподтверждённый возврат из бота живёт только в памяти процесса.

Удаление снимает профиль, карты, тексты, избранное, близких, диалог, оценки, streak и сессии. У платежа остаются идентификатор списания, сумма, валюта и период. Имя, дата рождения, место и переписка из этой строки убираются. Ссылка счёта очищается. Это описанная минимизация, не юридическая сертификация.

Очистка: кэш старше 14 дней по `valid_until`, история прогнозов и сообщения помощника старше 400 дней, запросы модели старше 90, отправленные и проваленные строки outbox старше 30, завершённые ключи идемпотентности старше 14, геокод старше 180. Ожидающие строки outbox и платёжные списания эта очистка не удаляет.

Причины. Один процесс не должен порождать массовую генерацию в рассылке. Аренда и уникальный ключ закрывают обычный повтор, но не обрыв между send и commit. Админ смотрит счётчики, а не карточки людей.

Альтернативы. Обещать exactly-once. Генерировать текст в момент рассылки. Считать ретроградность по чужому ежегоднику. Называть удаление сертификацией GDPR. Заменить страницу админа тремя командами бота.

Последствия. Живой Telegram, живой DeepSeek и живой платёж Stars этим решением не проверялись. Ретроспектива периода подписки по-прежнему не сделана. Публичный запуск закрыт до лицензии Swiss Ephemeris.

## D-047. Цена Stars только из окружения

Контекст. D-043 требовал, чтобы сумма счёта совпадала с `price_stars` в `plans.yaml`. На старте `PREMIUM_PRICE_STARS` сравнивался с этим полем и процесс завершался, если числа расходились. Поменять цену в окружении без правки файла было нельзя.

Решение. Сумма подписки и подарка — `PREMIUM_PRICE_STARS`, целое от 1 до 10000. `plans.yaml` это поле больше не содержит. Сроки, лимиты и правила функций остаются в файле. Новый счёт записывает текущую сумму из окружения. Неоплаченный счёт, сумма которого отличается от текущего окружения, теряет старую ссылку и получает новую на эту сумму. Платёж сверяется с суммой заказа на момент проверки. Оплаченный заказ не переписывается.

Причины. Одна сумма не должна жить в двух местах. Смена цены — настройка запуска, не правка тарифа.

Альтернативы. Оставить сверку и менять оба значения вместе. Хранить цену только в YAML.

Последствия. Фраза D-043 «цена совпадает с plans.yaml» для суммы Stars больше не действует. Экран берёт число из ответа API, не из константы. Живой платёж Stars по-прежнему не проверялся.

## D-048. Короткий JSON без режима thinking

Контекст. `deepseek-flash` и `deepseek-v4-pro` по документации DeepSeek думают по умолчанию. Бюджет `max_tokens` у прогноза и помощника маленький, от 180 до 400. Рассуждение занимает этот бюджет, `content` приходит пустым или обрезанным, разбор становится запасным текстом. Запасной payload записывался в общий кэш до конца окна и следующие открытия уже не звали модель.

Решение. Каждый вызов chat completion отправляет `thinking: {type: disabled}` и `reasoning_effort: none`. JSON-режим по-прежнему просит объект `{title, body}` или `{reply}`. Запасной payload с `source: fallback` не пишется в кэш. Уже записанный запасной текст при следующем чтении не считается попаданием: модель вызывается снова, удачный текст заменяет строку.

Причины. Разбор — короткий текст, не цепочка рассуждений. Пустой `content` нельзя показать как ответ модели и нельзя закрепить на весь день.

Альтернативы. Поднять `max_tokens` и оставить thinking включённым. Считать запасной текст успешным попаданием до `valid_until`.

Последствия. Живой вызов DeepSeek этим решением не проверялся. Если API всё же вернёт пустой `content`, экран снова покажет запасной текст, но следующее открытие повторит запрос. Ошибка вызова пишется в лог: модель, тип исключения, код статуса и короткий текст ответа API. Промпт, факты рождения и вопрос в эту строку не входят. Негодный JSON и запасной разбор пишутся отдельными событиями без текста модели.

## D-049. Шесть экранов альманаха

Контекст. Главная, календарь и premium уже собраны как типографический альманах. Профиль, полный прогноз, астропомощник, близкие, натальная карта и настройки оставались формой, абзацами и нижней плашкой темы.

Решение. Эти шесть экранов используют те же токены, шрифт и нижнюю навигацию. Новой библиотеки компонентов и второго механизма темы нет. Авторские строки остаются в `resources/texts/ru`. Иконки берутся из `static/icons/svg`. Отдельной иконки отправки нет: кнопка вопроса использует `arrow-right.svg`. Знак `natal-chart.svg` на экране карты подписан как иллюстрация раздела и не выдаётся за рассчитанные положения планет. Дома и асцендент не показываются как точные, если время или место неизвестны. Остаток вопросов помощника показывается только из поля `remaining` ответа API. Список сообщений этого поля не содержит, и клиент остаток не вычитает. Удаление данных открывается из «данные аккаунта» и по-прежнему требует отдельного подтверждения.

Причины. Один визуальный язык на всех основных экранах. Демонстрационные имена, даты и числа с эскиза не подменяют ответ сервера.

Альтернативы. Вторая палитра внутри страниц. Статичная картинка круга как персональная карта. Клиентское «17 из 20» без поля API.

Последствия. Маршруты, оплата, квоты и проверка `initData` не менялись. Живой DeepSeek и живой платёж Stars этим решением не проверялись.

## D-050. Обсерватория вместо альманаха

Контекст. Двенадцать экранов `design/mockup.jpeg` задают другой визуальный язык: тёмная поверхность, акцент `#8E94EA`, карточки и собственные компоненты. Прежний альманах и требование набирать подписи экрана строчными буквами с этим макетом расходятся.

Решение. Макет — источник правды для композиции, текстов и навигации этих экранов. Палитра одна, тёмная. Семейство шрифта остаётся Google Sans. Данные по-прежнему идут через типизированный клиент и TanStack Query. Строки, которых нет в API, живут во временных фикстурах с пометкой `TODO(api)` и не добавляют маршрутов бэкенда.

Причины. Пользователь прямо отменил прежний визуальный контракт, оставив шрифт и бизнес-логику.

Альтернативы. Оставить винную палитру и подогнать макет под неё.

Последствия. Светлая палитра не задана: сегмент «Светлая» сохраняет выбор, но не красит экран. Премиум-пользователь после времени рождения всё ещё ждёт место, а отдельного экрана места на макете нет. Живой DeepSeek и живой платёж Stars этим решением не проверялись.

## D-051. Регистр текста не принуждается

Контекст. D-009 требовал хранить авторские строки строчными и отклонять прописные в ответе модели. Это расходится с макетом и с обычной речью.

Решение. Авторский текст хранится в том регистре, в котором написан. Промпты не требуют строчных букв. Ответ модели не приводится к нижнему регистру и не отвергается из-за прописных. Emoji по-прежнему запрещены. `text-transform: lowercase` на документ и массовый `lower()` имени, кода, URL и email по-прежнему запрещены. Версии промптов прогноза увеличены, чтобы кэш не отдавал старый строчный текст как новый.

Причины. Пользователь отменил требование писать с маленькой буквы по всему проекту.

Альтернативы. Оставить запрет прописных только у ответа модели.

Последствия. D-009 в части строчного регистра не действует. Кэш прогнозов со старой версией промпта не переиспользуется. Живой DeepSeek этим решением не проверялся.

## D-052. Сетка натальной карты считается по долготам

Контекст. Новая иллюстрация `static/illustrations/png/natal_chart.png` — неподвижный круг знаков: 0° Овна сверху, дальше по часовой. Прежний ответ карты отдавал дома только названиями знаков, а числовые куспиды Placidus, которые уже считает `SwissEphemeris.houses`, отбрасывались.

Решение. `GET /api/v1/chart` отдаёт `house_cusps`: двенадцать эклиптических долгот или `null`, если дома не считались. Экран `/natal` рисует эти лучи и аспекты планет поверх иллюстрации, в той же ориентации. Пока долгот нет, сетка строится по фикстуре таблицы: Солнце 19°24′ Льва, Луна 4°12′ Рыб, Асцендент 12°03′ Скорпиона, равные дома от асцендента. Старый кэш карты с домами без долгот пересчитывается один раз.

Причины. Сетка должна меняться вместе с картой человека, а знаки на картинке сдвигать нельзя.

Альтернативы. Рисовать только равные дома от 0° знака асцендента. Тогда лучи совпадут со спицами иллюстрации и персонального сдвига не будет.

Последствия. Контракт карты расширен полем `house_cusps`. Это не новый маршрут. Живой DeepSeek и живой платёж Stars этим решением не проверялись.

## D-053. Остаток вопросов астропомощника приходит со списком

Контекст. Экран чата показывал зашитые «5 вопросов», а после ответа подставлял остаток из POST, где лимит периода — 20. Обновление списка сообщений снова затирало число заглушкой. Тот же ответ рисовался второй раз поверх уже сохранённой истории.

Решение. `GET /api/v1/assistant/messages` возвращает `{ messages, remaining }`. Чат берёт остаток оттуда и из ответа POST, без фикстуры. Повторный пузырь не рисуется, если этот текст уже есть в истории. Инвалидация кэша списка точная и не задевает другие ключи.

Причины. Пользователь видел два ответа на одно сообщение и скачущий остаток 5 → 20 → 5.

Альтернативы. Оставить список массивом и добавить отдельный маршрут квоты.

Последствия. Форма GET изменилась: это больше не голый массив. Новый маршрут не добавлен. Живой DeepSeek этим решением не проверялся.

## D-054. Промпт просит обычный регистр, сетка карты — замкнутая фигура

Контекст. После D-051 промпты остались набраны строчными, и модель копировала этот регистр. На карте отдельные лучи домов не сходились в фигуру. Удаление профиля пропало из вкладки «Профиль».

Решение. Системные промпты прогноза и астропомощника написаны обычным русским языком и прямо просят заглавную букву в начале предложения. Версии промптов увеличены, чтобы кэш не отдавал старый строчный текст. Внутренние линии карты соединяют долготы домов и планет в замкнутую фигуру, а не в отдельные радиусы. «Удалить данные» стоит внизу вкладки «Профиль» и открывает прежнее подтверждение.

Причины. Пользователь видит строчные ответы, разрозненные линии и отсутствие удаления.

Альтернативы. Оставить промпты строчными и надеяться, что модель сама сменит регистр. Оставить лучи домов.

Последствия. Кэш прогнозов со старой версией промпта не переиспользуется. Живой DeepSeek этим решением не проверялся: новый регистр ответа модели на живом ключе не смотрели.

## D-055. Отправленный вопрос виден до ответа модели

Контекст. Пузырь вопроса и ответ астропомощника появлялись вместе, когда POST уже вернулся. Пока DeepSeek молчал, экран выглядел так, будто сообщение ещё не ушло.

Решение. По нажатию отправки вопрос сразу рисуется как отправленный, а рядом встаёт пузырь астропомощника с индикатором загрузки. Когда ответ приходит, индикатор сменяется текстом ответа. Если история с сервера уже содержит эту пару, локальные пузыри уступают ей место. Пока пары в истории нет, локальный ответ остаётся на экране.

Причины. Человек должен видеть, что вопрос ушёл, и что астропомощник его читает, не дожидаясь конца запроса.

Альтернативы. Оставить оба пузыря до завершения POST. Рисовать только спиннер у кнопки отправки.

Последствия. Новый маршрут не добавлен. Живой DeepSeek этим решением не проверялся: задержку ответа в браузере держал тестовый маршрут, а не модель.

## D-056. Верх экрана начинается под шапкой Telegram

Контекст. На телефоне Mini App рисуется под статус-баром и кнопкой Close. У экрана был только фиксированный отступ 16px, поэтому приветствие и кнопка профиля оказывались под системным интерфейсом и шапкой Telegram.

Решение. Верхний, боковой и нижний отступы экрана и таб-бара прибавляют `--tg-safe-area-inset-*` и `--tg-content-safe-area-inset-*`. Это зона устройства и зона собственной шапки Telegram. Если переменных нет, остаётся прежний отступ макета. Фиксированный минимум в пикселях не подставляется.

Причины. Telegram сообщает эти зоны отдельно, и их нужно сложить. Макет 390×844 не содержит статус-бар, поэтому в браузере без Telegram отступ не растёт.

Альтернативы. Всегда держать 52px сверху. Рисовать собственную копию статус-бара.

## D-057. Тексты приложения начинаются с заглавной буквы

Контекст. Ресурсы интерфейса, бота и ошибок остались набранными строчными. На экране это читается как недописанная фраза.

Решение. Каждая авторская строка начинается с заглавной буквы, и так же начинается каждое следующее предложение. Подписи знаков, планет и фаз на экране получают заглавную букву при показе. Имена в расчёте, ключи и плейсхолдеры остаются прежними: «{name}, ваш знак» не превращается в «Ваш» после запятой.

Причины. Пользователь попросил поднять регистр всех текстовок приложения.

Альтернативы. Менять регистр только у строк макета. Писать каждое слово с заглавной.

## D-058. Пустое время рождения значит «не знаю»

Контекст. На экране рождения тумблер «Не знаю время» отключал поле. Правка уже готового профиля открывает тот же экран, но шаг там «done», и «Продолжить» отправлял время только на шаге «time». Новое время не доходило до профиля.

Решение. Тумблера нет ни при регистрации, ни при правке профиля. Пустое поле времени отправляет `birth_time_unknown: true` и очищает сохранённое время. Заполненное поле отправляет время и `birth_time_unknown: false`. Готовый профиль сохраняется через PATCH `/profile`, а не через черновик шага.

Причины. Пользователь просил убрать тумблер и считать незаполненное поле неизвестным временем. Время из правки профиля должно сохраняться.

Альтернативы. Оставить тумблер и отдельно чинить шаг «done». Подставлять полдень, когда поле пустое.

Последствия. Карта по-прежнему помечает ограничение `time_unknown`, если время не задано. Время не выдумывается.

## D-059. Совместимость без заранее сохранённого близкого

Контекст. Экран совместимости открывался только по уже сохранённому человеку. Чтобы сравнить двоих, их сначала нужно было добавить в «Близкие».

Решение. `/compatibility` принимает двоих на месте. Каждый может быть собой, уже сохранённым близким или новыми данными. Пустое время значит, что время неизвестно. Если новый человек ещё не в списке, тумблер «Сохранить в близкие» записывает его, в том числе время. Ссылка `/compatibility/:personId` по-прежнему выбирает этого человека вторым. На «Сегодня» внизу стоит кнопка «Совместимость».

Причины. Пользователь хочет сравнить двоих сразу и сохранить близкого только если сам включит тумблер.

Альтернативы. Оставить обязательное добавление в «Близкие». Считать совместимость только по себе и одному близкому.

Последствия. Три строки разбора на экране остаются подписью макета: отдельного ответа API на произвольную пару нет. Сохранение идёт в существующий `POST /related`.

## D-060. Разбор темы открывается с Premium

Контекст. Кнопки тем вроде «Любовь», «Работа», «Диалог» и «Эмоции» либо открывали общий прогноз, либо ничего не делали. Разбор темы на сервере уже закрыт подпиской.

Решение. Нажатие такой кнопки при активном Premium запрашивает разбор темы и показывает его текст. Без Premium запрос не уходит: на экране появляется сообщение, что функция только с Premium, и кнопка «Подключить».

Причины. Пользователь хочет читать расширенный текст по теме и сразу видеть, что без подписки он закрыт.

Альтернативы. Оставить переход на общий прогноз. Показывать пустой экран вместо сообщения.

## D-061. Чат астропомощника пишет только с Premium

Контекст. Помощник на сервере уже требует подписку: без неё вопрос не сохраняется и модель не вызывается. Поле чата при этом оставалось открытым, и отказ приходил только после отправки.

Решение. Без Premium поле и кнопка отправки закрыты, запрос не уходит. Старые сообщения остаются на экране. В пустом чате легенда говорит, что писать и отправлять можно с Premium. Если переписка уже есть, та же фраза стоит над полем.

Причины. Пользователь просил заблокировать ввод без подписки и написать об этом в легенде чата.

Альтернативы. Оставлять поле открытым и показывать отказ ответом модели. Прятать всю историю вместе с полем.

## D-062. Совместимость открывается после связи со звёздами

Контекст. Карточки пары появлялись на том же экране сразу, как только оба человека были заполнены. Переход выглядел мгновенным и смешивал выбор с результатом.

Решение. Сначала выбираются двое, внизу кнопка «Проверить». Она закрыта, пока пара не собрана. Нажатие открывает экран «Связь со звёздами» на две секунды, затем карточки, схему и три строки как на макете. «Назад» с этих шагов возвращает к выбору, данные пары сохраняются. При `prefers-reduced-motion` пауза и вращение пропускаются, результат показывается сразу.

Причины. Пользователь просил отдельный экран результата и короткую паузу, чтобы расчёт не выглядел мгновенным.

Альтернативы. Оставить результат на экране выбора. Ждать две секунды даже при отключённой анимации.

## D-063. Текст прогноза появляется только после ответа

Контекст. Пока чтение дня, прогноз или тема ещё не пришли, экран подставлял заготовленную фразу. Запасной текст модели тоже выглядел как готовый ответ. Ожидание базы и ожидание генерации для человека не различались: и там и там уже был чужой текст.

Решение. Пока запрос к кэшу или статус `pending`/`idle`, на месте текста стоит загрузка. Готовый ответ со статусом `ready` заполняет поле. Ошибка сети, ошибка чтения и запасной текст показывают «Не удалось связаться со звёздами». Закрытый Premium и нехватка данных рождения остаются своими сообщениями. Повторный запрос того же чтения идёт с одним ключом идемпотентности, а пока генерация не закончилась, клиент спрашивает сохранённый результат, не начиная новый вызов модели.

Причины. Пользователь просил не заполнять поля текстом во время ожидания нейронки и базы и подставлять тематическую фразу, если ответа нет.

Альтернативы. Оставить запасной абзац как видимый ответ. Показывать заготовку макета, пока кэш не ответил.

## D-064. Тема на «Сегодня» ждёт текст модели

Контекст. Кнопки «Любовь», «Работа» и соседние с первого нажатия показывали «Не удалось связаться со звёздами». Запрос ещё был в работе: первый вызов модели не успевал, запасной текст публиковался сразу, а удачная попытка дописывалась в кэш уже после закрытия окна.

Решение. Пока чтение темы не готово, во всплывающем окне стоит загрузка. Если первая попытка не дала текст модели, та же генерация дожидается следующей попытки и только потом закрывает чтение. Готовый текст заполняет окно. Стрелка в карточке «Открыть прогноз» прижата к правому краю контейнера.

Причины. Пользователь видел пустой отказ с первого нажатия и просил дождаться ответа нейронки, не обрывая окно коротким ожиданием.

Альтернативы. Увеличить только таймаут HTTP и по-прежнему показывать запасной текст. Оставить стрелку сразу после заголовка.

## D-065. Поле чата не уезжает вместе с перепиской

Контекст. Сообщения и поле ввода были одной колонкой на всю высоту страницы. Длинный диалог уводил поле ниже экрана, и писать можно было только долистав до конца. Аватар астропомощника стоял у верхнего края пузыря.

Решение. Экран чата занимает высоту окна. Листается только лента сообщений. Число оставшихся вопросов и поле ввода остаются над таб-баром. Аватар астропомощника выровнен по нижнему краю сообщения.

Причины. Пользователь просил, чтобы поле всегда было видно, и чтобы аватар был снизу сообщения, а не сверху.

Альтернативы. Оставить прокрутку всей страницы и приклеивать поле через `sticky`. Оставить аватар у первой строки.

## D-066. Админ видит людей и выбирает, кому выдать Premium

Контекст. Страница админа показывала только счётчики и форму, куда идентификатор человека нужно было вписать вручную. Сводка по-прежнему не содержит имён. Выдать период без списка было не из чего.

Решение. Отдельный запрос для администратора отдаёт открытые учётные записи: имя, имя в Telegram, числовой id и есть ли сейчас Premium. Дата рождения, место и переписка в этот ответ не входят. На странице строка выбирается в уже существующую выдачу периода: дни, причина и подтверждение остаются обязательными, выдача пишется в аудит как раньше. Список — не больше 200 последних открытых записей.

Причины. Пользователь просил в админ-панели смотреть людей и выдавать им Premium.

Альтернативы. Оставить ввод UUID вручную. Показывать в списке дату рождения и тексты. Выдавать период одним нажатием без причины и подтверждения.

## D-067. Вход в админку со вкладки «Профиль»

Контекст. Строка «Админ» осталась на старой странице профиля. Текущий экран вкладки её не рисует, поэтому человек из `ADMIN_IDS` не видит переход.

Решение. На вкладке «Профиль» после «Моя подписка» появляется строка «Админ», если в сессии `is_admin`. Она открывает `/admin`. У остальных этой строки нет.

Причины. Пользователь вставил свой Telegram id в `ADMIN_IDS` и не нашёл панель на вкладке.

Альтернативы. Оставить переход только прямым адресом `/admin`. Показывать строку всем.

## D-068. Профиль разделяет правку, близкого и действующую подписку

Контекст. Аватар на вкладке «Профиль» открывал список близких. «Моя подписка» всегда предлагала купить период, даже если он уже был. Имя, дата и короткое предсказание стояли вплотную. Отдельной строки, чтобы добавить близкого, в списке не было.

Решение. Аватар открывает правку даты и времени рождения. Строка «Добавить близкого» открывает форму нового человека. «Моя подписка» при действующем периоде показывает три возможности и сколько дней осталось до `access_until`. Покупка остаётся, только когда периода нет. Между именем и датой зазор 16px, перед предсказанием 40px.

Причины. Пользователь просил не предлагать подписку повторно, править профиль с аватара, добавить близкого из списка и раздвинуть три строки шапки.

Альтернативы. Оставить аватар переходом к близким. Показывать цену и «Подключить» поверх действующего периода. Держать имя, дату и предсказание без зазора.

## D-069. Тёмная тема по умолчанию, светлая по выбору

Контекст. Переключатели «Авто», «Светлая» и «Тёмная» записывали выбор, но цвета оставались тёмной палитрой макета: светлого набора токенов не было. Блок уведомлений и строки времени стояли вплотную.

Решение. Пока человек не выбрал тему, стоит тёмная. «Светлая» подменяет те же токены на светлые и сразу красит экран. «Тёмная» возвращает палитру макета. «Авто» следует схеме Telegram, а если её нет — тоже тёмной. Тема, карточка уведомлений, время, пояс и помощь разделены одним зазором 24px.

Причины. Пользователь просил тёмную тему по умолчанию, рабочую светлую и равные расстояния между уведомлениями и временем.

Альтернативы. Оставить только тёмную палитру. Красить светлую тему отдельными цветами в компонентах. Сдвинуть только одну пару блоков.

## D-070. Совместимость и натальный разбор спрашивают разное

Контекст. Строки «Диалог», «Эмоции» и «Общие ориентиры» открывали тот же запрос темы, что и дневной гороскоп. Промпты дня, пары и карты почти не отличались. «Разбор» натальной карты был одной фразой на знак.

Решение. Каждый вид текста называет свою задачу и запрещает чужую. Строка пары уходит в синастрию с целью и двумя знаками, не в тему дня. «Разбор» при открытой карте ждёт отдельный подробный текст не короче двенадцати предложений. Пока Premium нет, на экране остаются более длинные подписи рассчитанных точек. Версии промптов увеличены, чтобы старый общий кэш не подменил новый текст.

Причины. Пользователь видел в совместимости те же слова, что в обычном гороскопе, и просил типизировать каждый запрос. Разбор карты был слишком коротким.

Альтернативы. Оставить три строки на темах «отношения» и «эмоциональное состояние». Удлинить только запасные фразы и не звать модель. Писать один общий промпт на все виды.

## D-071. Админ-панель оставляет только выдачу Premium

Контекст. На странице админа рядом с выдачей периода стояли интервал счётчиков и форма возврата. После успешной выдачи поля оставались заполненными, а список людей не перечитывался.

Решение. На странице остаются список людей и форма выдачи. Счётчики, даты и возврат с неё убраны. Возврат по-прежнему доступен командой бота. После ответа 204 поля и подтверждение возвращаются к пустому виду, дни — к 7, и список людей запрашивается снова.

Причины. Пользователь просил после успешной выдачи стирать введённое и обновлять список, а всё остальное с панели убрать.

Альтернативы. Оставить возврат и счётчики на странице. Стирать поля, не перечитывая список. Удалить саму команду возврата.

## D-072. Список админа — таблица со страницами

Контекст. Люди на странице админа шли одним списком, и сервер отдавал не больше двухсот последних записей. Дальше листаться было некуда.

Решение. `GET /admin/users` принимает `page` и `page_size` и отдаёт страницу вместе с общим числом. На экране это таблица: имя, Telegram, id, Premium и выбор в форму выдачи. Страница по умолчанию — 10 человек. Кнопки «Предыдущая» и «Следующая» ходят по страницам, после выдачи перечитывается текущая.

Причины. Пользователь просил таблицу и пагинацию.

Альтернативы. Резать те же двести записей на страницы только в браузере. Оставить маркированный список.

## D-073. Тема по умолчанию совпадает с Telegram

Контекст. Пока человек не выбирал тему, приложение записывало тёмную палитру и не смотрело на схему Telegram. В светлом Telegram экран оставался чужим.

Решение. Пустой выбор значит «Авто»: светлая или тёмная палитра берётся из `colorScheme` Telegram. Если схемы нет, остаётся системная. «Светлая» и «Тёмная» по-прежнему фиксируют палитру, пока человек сам их не сменит.

Причины. Пользователь просил, чтобы по умолчанию тема была как в Telegram.

Альтернативы. Оставить принудительно тёмную. Всегда брать светлую.

## D-074. Карта на «Сегодня», история вне профиля, избранное в общем стиле

Контекст. Натальная карта с «Сегодня» открывалась только шевроном карточки дня. В профиле была строка «История». Страница избранного оставалась прежней вёрсткой со списком абзацев.

Решение. Под категориями дня стоит кнопка «Натальная карта» и открывает `/natal`. Шеврон карточки дня ведёт туда же. Строка «История» с профиля убрана, адрес `/history` сохранён. Избранное собирается из шапки, строк списка и пустого состояния в палитре приложения.

Причины. Пользователь просил кнопку карты на экране «Сегодня», убрать историю из профиля и переделать избранное в стиле приложения.

Альтернативы. Оставить только шеврон. Удалить адрес `/history`. Оставить избранное старой страницей.

## D-075. Поля близкого на равном зазоре, силуэты загрузки переливаются

Контекст. На «Близких» имя, дата и «Сохранить» стояли плотнее, чем кнопка под ними. Пока список или текст ещё ехали, силуэты строк были плоской заливкой, и ожидание не читалось.

Решение. Строки близких, имя, дата рождения, «Сохранить» и «Добавить человека» делят один зазор 24px. Пока список грузится, на их месте три силуэта той же высоты. Силуэты строк и строк текста получают блик, который проходит по поверхности. При `prefers-reduced-motion` блик не играет: общее правило уже гасит анимацию.

Причины. Пользователь просил раздвинуть поля на вкладке добавления близкого и показать, что загрузка ещё идёт.

Альтернативы. Оставить зазор 12px. Крутить спиннер вместо блика на силуэтах.

## D-076. Крупные блоки экрана делят один зазор

Контекст. Колонки экранов не имели общего зазора. Шапка прилипала к следующему блоку, карточки и поля стояли вплотную, а прежние внешние поля складывались с новым зазором вдвойне.

Решение. Прямые блоки экрана и внутренняя колонка делят зазор 24px. Списки карточек, поля и нижние действия используют тот же шаг. Поля, которые дублировали этот зазор, обнулены. Строки одного списка с разделителем остаются вместе. Приветствие, имя и дата на «Сегодня» ближе друг к другу, на 12px.

Причины. Пользователь просил пройти проект и раздвинуть блоки, которые приклеены друг к другу.

Альтернативы. Оставить нулевой зазор там, где так нарисован макет. Ставить разный зазор на каждом экране вручную.

## D-077. Баланс звёзд без Premium

Контекст. Без подписки натальная карта, совместимость и вопросы астрологу были закрыты целиком. Пользователь попросил разовую цену и пополнение баланса со экрана «Сегодня».

Решение. Без Premium одна совместимость стоит 40 звёзд, одна натальная карта 40, один вопрос астрологу 20. С Premium эти три вещи остаются в периоде: карта и синастрия открыты, у помощника прежние 20 вопросов. Баланс растёт только после проверенного `successful_payment` по заказу `topup`. Статус `openInvoice` баланс не меняет. Списание совместимости одно на пару знаков, карты — одно на человека, вопроса — одно на ключ и только после сохранённого ответа. Справа сверху на «Сегодня» стоит баланс. Нажатие открывает пополнение: 10, 20, 50, 100 или своя сумма, «Оплатить», упоминание Premium и ссылка на t.me/PremiumBot. Профиль остаётся на вкладке.

Причины. Пользователь задал цены и попросил окно пополнения вместо кружка профиля.

Альтернативы. Оставить три функции только за Premium. Считать оплату по статусу окна Telegram. Списывать каждый из трёх разборов пары отдельно.
